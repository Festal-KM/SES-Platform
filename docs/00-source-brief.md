## 1. 目的・背景

- 自社エンジニア／取引先（他社）エンジニアを一元管理し、案件管理〜提案〜契約〜稼働後フォローまでの業務を Web 上で完結させる。
- 営業活動の属人化（Excel / メール / チャットツール分散）を解消し、検索性・可視化・トレーサビリティを高める。

## 2. 対象範囲（スコープ）

**対象**

- エンジニア管理（スキル・スキルシート・稼働状況など）
- 取引先企業管理（企業アカウント／営業アカウント）
- 案件管理（要件・単価・期間・勤務地等）
- マッチング（案件要件 × スキル）
- コミュニケーション（チャット）
- 提案履歴（誰をどの案件に提案したか）
- 契約管理（NDA / 基本契約 / 発注書 / 請求書等）
- 稼働後管理（延長確認、契約更新）

**対象外（別フェーズ検討推奨）**

- 給与計算、勤怠、反社チェック、与信審査など重い基幹領域

## 3. 利用者・権限設計（ロール）

- 自社管理者（Admin）: 全データ閲覧・設定・権限付与
- 自社営業（Sales_Internal）: 案件作成、提案、チャット、契約進行
- 取引先企業管理者（Partner_Admin）: 自社企業配下の営業／エンジニア管理
- 取引先営業（Partner_Sales）: 自社登録エンジニアの更新、案件閲覧（範囲制御）、チャット、提案
- （任意）閲覧専用（Viewer）: 参照のみ

> 重要: マルチテナント設計（取引先ごとにデータ分離）と、「自社は全体見える／取引先は自社データだけ見える」を権限で担保。

## 4. 機能一覧（大項目 → 中項目）

### 4.1 エンジニア管理

- エンジニア基本情報（所属、稼働状況、単価目安、希望条件）
- スキルセット（タグ／カテゴリ／経験年数／レベル）
- メモ（営業メモ、面談所見、注意事項）
- スキルシート格納（Excel / Word / PDF アップロード、版管理）
- 検索・フィルタ（スキル、稼働開始日、単価帯、勤務地、リモート可否）

### 4.2 取引先企業管理（アカウント階層）

- 企業アカウント（1 社 = 1 テナント）
- 企業配下に営業アカウントを複数作成
- 企業情報（契約状況、請求条件、支払いサイトなど）

### 4.3 案件管理

- 案件登録（案件名、概要、必須／尚可、単価、期間、場所、面談回数、商流、募集人数、開始日）
- 公開範囲設定（自社のみ／特定パートナーのみ／全パートナー等）
- ステータス管理（募集中／選考中／決定／クローズ）

### 4.4 マッチング

- 案件要件（必須／尚可）とスキルを照合
- マッチ度スコア（例: 必須一致 = 高、尚可一致 = 加点、経験年数で加点）
- 結果一覧（自社・他社を混在表示、権限により見える範囲を制御）
- マッチ候補から「提案作成」へ遷移

### 4.5 提案管理（誰をどの案件に提案したか）

- 提案登録（案件 × エンジニア × 提案先企業／担当者）
- ステータス（提案中／面談調整／面談実施／結果待ち／決定／見送り）
- 履歴（日時、担当者、メモ、添付）
- 重複提案アラート（同一案件に同一エンジニアを再提案など）

### 4.6 チャット（コミュニケーション）

- 案件単位 or 企業単位のスレッド
- 添付（スキルシート共有、契約書ドラフト共有）
- 監査ログ（誰が何を送ったか）※重要

### 4.7 契約・請求関連

- ドキュメント管理（NDA / 基本契約 / 個別契約 / 発注書 / 請求書）
- テンプレート＋差し込み（会社名、住所、案件情報、単価、期間など）
- 電子署名連携（推奨）
- 契約ステータス（ドラフト／先方確認中／締結済／失効）

### 4.8 稼働後管理（延長確認など）

- 契約満了日管理
- 延長確認タスクの自動生成（例: 満了 60 日前／30 日前）
- 単価改定交渉の起票（改定希望、根拠、履歴）
- 稼働中ステータス、離任予定、後任提案

## 5. 主要画面（案）

- ログイン／パスワードリセット
- ダッシュボード（案件数、提案進捗、満了アラート、最近のチャット）
- エンジニア一覧／詳細／編集
- 案件一覧／詳細／編集
- マッチング画面（案件 → 候補一覧、スコア順）
- 提案一覧／詳細（進捗ボード形式も可）
- 取引先企業管理（企業／営業アカウント／権限）
- チャット（スレッド一覧／メッセージ）
- 契約／ドキュメント（一覧／アップロード／テンプレ生成／ステータス）
- タスク（延長確認・契約更新・面談調整の ToDo）

## 6. データ設計（エンティティ概要）

最低限のテーブル（例）: 会社／テナント、ユーザー、権限、エンジニア、エンジニア × スキル、スキル辞書、スキルシート等ファイル、案件、案件要件、計算結果キャッシュ（任意）、提案、提案履歴、チャット、契約、契約書等ファイル、請求／発注、延長確認など

## 7. 非機能要件（最低限）

### 7.1 セキュリティ

- テナント分離（Row Level Security 相当の実装）
- 2FA（管理者／自社営業は推奨）
- IP 制限（任意）
- 監査ログ（閲覧・DL・編集・削除）
- ファイルのウイルススキャン（アップロード時）

### 7.2 性能・運用

- 検索: スキル × 条件の複合検索（インデックス設計）
- バックアップ／復旧手順
- 通知（メール／アプリ内通知）: 提案結果、満了アラート

## 8. 追加したほうがいい機能（優先度つき）

**優先度: 高（入れないと運用が辛い）**

1. 通知・タスク機能（延長確認、面談日、満了、契約締結待ち）
2. 権限の細分化（閲覧範囲、DL 制限、取引先ごとの公開制御）
3. 変更履歴／監査ログ（誰がいつ何を変えたか）
4. 重複・整合性チェック（同姓同名、同一エンジニアの二重登録、提案重複）
5. スキル辞書（マスタ統一）— 表記ゆれ対策（Java / JavaSE / Java8 等）

**優先度: 中（あると強い差別化）**

6. 電子署名連携（クラウドサイン / DocuSign 等）
7. メール取り込み or 送信テンプレ（提案メール、面談調整の定型化）
8. 募集〜決定の KPI ダッシュボード（提案 → 面談 → 決定率、会社別、案件別）
9. ファイル版管理（スキルシート更新履歴、最新版フラグ）

**優先度: 低（後からでもよいが便利）**

10. 面談メモのフォーマット化（評価項目テンプレ）
11. タグによる運用設計（商流、得意領域、要注意フラグ）
12. API 連携（会計、勤怠、SFA 等）

## 9. 開発の進め方（おすすめ MVP 分割）

- Phase 1（MVP）: エンジニア管理／案件管理／検索／提案履歴／権限（最小）
- Phase 2: マッチング精度向上／チャット／通知・タスク
- Phase 3: 契約テンプレ・電子署名／請求発注の高度化／KPI 分析

## 付記: `CLAUDE.md` で確定させた差分

本ファイルは元ドラフトであり、以下は `CLAUDE.md` 側で確定・変更した点である（`CLAUDE.md` が正）。

| 論点 | 元ドラフト | `CLAUDE.md` での確定 |
|---|---|---|
| 提供形態 | 明記なし（自社ツールとも読める） | **SES 企業向け SaaS**。テナント = 契約 SES 企業（§1.4 / §10） |
| 「1 社 = 1 テナント」の意味 | 取引先企業 1 社 = 1 テナント | テナントは契約 SES 企業。**取引先はテナント内の `PartnerCompany`（第二境界）**（§3.1） |
| 情報境界 | 「権限で担保」 | 越境は**案件公開／提案／チャット参加の 3 経路のみ**。パートナー同士の相互参照は 1 経路も作らない（§3.1） |
| 品質ゲート | 記載なし | 外部共有物は **PII 層／商流層／整合層の 3 層ゲート**を必ず通す（§3.3） |
| 提案ステータス | 提案中／面談調整／面談実施／結果待ち／決定／見送り | `GATE_FAILED` / `SUBMIT_FAILED` / `LOST` を**別状態として分離**（§4.2） |
| AI 利用 | 記載なし | スキルシート解析・スキル正規化・根拠文生成に利用。**マッチング順位は LLM に決めさせない**（§3.2 / §12） |
| 対象外 | 給与計算・勤怠・反社・与信 | 上記に加え、**エンジニア本人向けアプリ／求人媒体化**と**稼働工数管理**を追加（§6） |
