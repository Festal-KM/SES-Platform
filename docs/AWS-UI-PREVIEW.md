# AWS 画面プレビュー

2026-11-06、宮田の承認で、見た目の調整をすぐ確かめるため AWS 開発 VM に専用の Next.js 開発サーバーを設けた。PC 側でアプリや DB を起動しない。正式な開発画面とは別の作業コピーを使い、CI や main への反映を待たずに画面の変更を確認できる。

## 接続

開発 VM が起動中であることを `node scripts/aws-development.mjs status` で確認する。PC の 3001 番を他のプロセスが使っていないことを確かめ、リポジトリのルートから次を実行する。

```powershell
node scripts/aws-connect-development.mjs 3001
```

ターミナルを開いたまま `http://localhost:3001/signin` を開く。Session Manager plugin と各自の AWS 認証が必要。SSH や 3001 番を外部に公開しない。接続を終えるときはこの転送だけを終了する。VM の停止は共有利用者を確認してから行う。

## 画面の更新

このプレビューは `/workspaces/ses-ui-preview` の独立したコピーで動く。表示対象の既存 TSX または CSS ファイルを編集したら、次のように 1 ファイルずつ送る。

```powershell
node scripts/aws-preview-update.mjs 'apps/web/app/(main)/projects/[id]/project-card-editor.tsx'
```

表示される確認コマンドで SSM の `Success` を確認し、ブラウザで再読み込みする。初回の画面表示やコンパイルには時間がかかる。転送できるのは `apps/web/app/` 配下の既存 `.tsx`・`.css` のみ。API、共通パッケージ、文言、依存関係、ファイルの追加や削除はこの手順では反映できない。プレビューの基準は作成時の開発画面のコピーであり、main の変更は自動で同期されない。対象外の変更や古い基準では正式な開発環境で確認する。

## データと制約

プレビューは開発用 DB・Redis を正式な開発画面と共有する。**編集や削除は共有データにも反映されるため、表示確認に使う。** 添付用の S3 互換サービスはプレビュー専用で、正式な開発画面の添付とは共有しない。添付やジョブの動作確認には使わない。実送信を許可しない開発設定は維持する。

VM の再起動後もコンテナは再起動する設定だが、接続は再度必要。起動・再開後は画面の応答を確認する。プレビューでの確認は PR の CI や main からの開発環境への反映を代替しない。
