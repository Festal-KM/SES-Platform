## 1. 何を作るか

チャット・スレッドの投稿にファイルを 1 つ添えて送る。相手は画面からダウンロードできる。

```
送る人                       相手
[ファイルを選ぶ] → 送信
  「検査中」（自分にだけ見える）   （まだ何も見えない）
       ↓ ウイルス検査（CLEAN）
       ↓ 本文の取り出し → 品質ゲート（個人情報・商流）
       ↓ PASS（承認）
  「送信済み」                  ファイルが見える・ダウンロードできる
       ↓ FAIL
  「送れませんでした（理由）」     （何も見えない。存在も分からない）
```

## 2. 🔴 守らなければならないこと（`CLAUDE.md`）

| ルール | 出所 | この案での守り方 |
|---|---|---|
| ウイルス検査が `CLEAN` になるまで共有 URL を出さない | §3.4 | 既存の `issueDownloadUrl`（共有 URL を出す唯一の関数）を通す |
| チャット添付は品質ゲートを通す | §3.3 | `CHAT_ATTACHMENT` のゲート（種別は既に定義済み・未配線） |
| ゲートの FAIL を「無視して送信」できない | §3.3 | 直せるのは元のファイルだけ（差し替えて送り直す） |
| ファイルの原本を無加工で LLM に送らない | §3.2 / `BR-11` | 本文を**機械的に取り出して**マスキングしたテキストだけをゲートに渡す（§3） |
| 検査中の添付は相手に見せない | `F-038` AC-3 | 相手側には行ごと出さない（「何か送られてくる」ことも見せない） |
| 運営者に中身を見せない | §10.5 | `messages.attachment_key` は運営者に GRANT 済みでない（既存） |

## 3. 🔴 いちばん大きな論点: ゲートはファイルの中身を読めない

今の品質ゲート（`gate-inspector`）は**マスキング済みのテキストしか受け取れない**（`packages/ai` は画像・文書のブロックを受け取らない）。スキルシートの外部共有（`SKILL_SHEET_SHARE`）が Phase 1 で**わざと通らない（fail-closed）**のはこのためである（`docs/05` §11.11 ⑤）。

**提案: ファイルから本文を機械的に取り出す工程（AI を使わない）を足す。**

| 工程 | 中身 |
|---|---|
| `file.extract-text`（新しいジョブ） | `CLEAN` になったファイルから本文を取り出す（PDF のテキスト層 / docx / xlsx / csv / txt）。**AI を使わない**ライブラリで行う |
| マスキング | 既存の `packages/ai` の入口（`mask.ts`）を通す |
| ゲート | マスキング済みテキスト + ファイル名で、PII 層・商流層を判定。整合層はチャット添付には無い |

- 🔴 **本文を取り出せないファイルは送れない**（画像、スキャンした PDF、パスワード付きのファイル）。取り出せないものを PASS にしない（fail-closed）。画像は OCR が入るまで対象外
- 🔴 **この工程はチャット専用ではない。** スキルシートの外部共有（`SKILL_SHEET_SHARE`）と、スキルシート解析（`F-032` / `sheet-parser`）も同じ「ファイルから本文を取り出す」を必要としている。**共通の土台**として作るのがよく、そのため宮田さんと分担を決めたい（§9 の 1）

## 4. データの持ち方

`messages` には添付の列が既にある（`attachment_key` / `attachment_scan_status` / `review_gate_id`。今は使っていない）。足すのは次だけ。

| 変更 | 中身 |
|---|---|
| `attachment_content_type` | `text NULL`。MIME |
| `attachment_byte_size` | `bigint NULL` |
| `attachment_state` | `text NULL`。`SCANNING` / `EXTRACTING` / `GATE_RUNNING` / `APPROVAL_PENDING` / `SHARED` / `BLOCKED`（CHECK）。🔴 相手に見えるのは `SHARED` だけ |
| CHECK | 添付の列は「全部ある」か「全部ない」か |
| ファイル名 | 🔴 **保存するかは論点**（§9 の 4）。スキルシートは原本のファイル名を保存していない（`山田太郎_スキルシート.xlsx` のように氏名が入りうる）。保存するならゲートの検査対象に含める |

- オブジェクトのキーは `docs/05` §14.1 が既に予約している `t/{tenantId}/chat/{threadId}/{messageId}/{uuid}.{ext}`
- ウイルス検査の結果を書き込む SQL 関数（`app_apply_scan_status`）は今 `skill_sheets` しか更新しない → `messages` にも広げる
- 保持期間・解約時の削除（`PURGE_SPEC`）は `attachment_key` を既に対象にしている（オブジェクトも消える）

## 5. 承認（`CLAUDE.md` §3.3）

既定は**人間の承認が必須**。チャットの往復の速さと両立させる案:

| 案 | 中身 |
|---|---|
| **A（推奨）** | ゲートが**全層 PASS** のとき、テナントの `autoApproveEnabled` が有効なら自動で相手に見せる（承認者は `system`、監査ログに残る）。無効なら、ホストの `SALES` 以上が承認する |
| B | 毎回ホストが承認する |

- 🔴 **1 層でも FAIL なら送れない**（差し替えて送り直す）
- 取引先から送るファイルも同じ流れ。🔴 取引先がスキルシートを添付しようとすると、氏名などで PII 層が FAIL する —— スキルシートは**提案（経路 2）で送る**ものであり、チャットで素通しにしない

## 6. API（`docs/05` §6.5 の変更案）

| # | 変更 | 中身 |
|---|---|---|
| 新 | `POST /api/threads/{id}/attachments/upload-url` | `{ contentType, byteSize }` → 署名付き PUT。**キーはサーバが組む**（入力で受けない。スキルシートの #18 と同じ） |
| 51 | `POST /api/threads/{id}/messages` | `{ body, attachmentUploadToken? }`。アップロードを確定し、`attachment_state = SCANNING` で行を作る |
| 50 | `GET /api/threads/{id}/messages` | 添付の要約（種類・大きさ・状態）を足す。🔴 相手には `SHARED` の行だけ |
| 新 | `POST /api/threads/{id}/messages/{messageId}/attachment/download-url` | `issueDownloadUrl` を通す（`CLEAN` + ゲート PASS + 監査ログ） |

- 監査: `chat_attachment.upload` / `chat_attachment.download` を足す（`docs/05` §16.1 に未定義）
- 上限: 1 ファイル 20 MiB（`UPLOAD_MAX_BYTES`）。受け付ける種類: PDF / docx / xlsx / csv / txt（§3 で本文を取り出せるもの）
- 容量は `UsageCounter`（`STORAGE_BYTES`）、ゲートの実行は `F-026` の件数クォータに数える（1 ファイル = 1 回。投稿ごとではない）

## 7. 画面（`S-031`）

- コンポーザーにクリップのボタン（今は「押して何も起きない導線を置かない」で外している）
- 自分の投稿: ファイルの Card（種類・大きさ）+ 状態（検査中 / 承認待ち / 送信済み / 送れませんでした + 理由）
- 相手の投稿: `SHARED` のファイルだけ Card で出し、押すとダウンロード
- スレッド情報パネルに「ファイル」の一覧（送信済みのものだけ）
- モバイル（Tier 1）: スマホから送れる・受け取れる

## 8. テスト

| 種類 | 確かめること |
|---|---|
| 分離テスト | 🔴 検査中・FAIL の添付は相手に**行ごと**見えない / 他社は添付の存在を知れない / ダウンロード URL は `CLEAN` + PASS のときだけ / キーを入力で差し替えられない |
| 単体 | 本文の取り出し（取り出せないものは fail-closed）/ 状態の遷移 / マスキングを経た入力だけがゲートに渡る |
| E2E | ホストが PDF を送る → 取引先がダウンロード（監査ログ 1 件）/ 氏名入りのファイルが FAIL して相手に届かない |
