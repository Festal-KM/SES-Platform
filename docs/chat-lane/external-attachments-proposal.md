# 提案: チャットの添付を、取引先がいる部屋でも送れるようにする（CLAUDE.md §3.3 の変更）

> **状態: 提案（宮田さんの承認待ち）。** `CLAUDE.md` の改訂は人間の承認事項（§8.6）。紺野は 2026-10-27 に「外部に出せるようにしてくれ」と決めた。この PR で宮田さんの承認を取り、承認後に `CLAUDE.md` を書き換える（書き換えは紺野か宮田が行うか、明示の許可を得て Claude が行う）。
> 関連: `docs/chat-lane/attachments-proposal.md`（#108。ゲートを通す案）/ `docs/02` `F-038` 改訂 12（社内だけの部屋で先に作る分）。

## 1. 何を変えるか

今の `CLAUDE.md` §3.3 は、チャット添付を「テナント外へ共有されるもの」として**必ず `ReviewGate` を通す**ものに入れている。

ゲートはファイルの中身を読めない（マスキング済みのテキストしか受け取らない）ので、ゲートを通すには**ファイルから本文を取り出す工程**を新しく作る必要がある（#108 の §3）。紺野は、それを待たずに**注意書きで扱って送れるようにする**ことを選んだ。

## 2. 変更後の §3.3（案）

> - **テナント外へ共有されるもの**（提案、スキルシート、案件の公開、~~チャット添付~~、**契約書**）は**必ず `ReviewGate` を通す**。**チャット添付は 2026-10-27 にゲートの対象から外した**（紺野の決定・宮田の承認）。ゲートの代わりに次の 4 つで扱う:
>   1. 送る前に「個人情報（氏名・連絡先など）の扱いに注意してください。スキルシートは提案から送ってください」を常に出す
>   2. ウイルス検査が `CLEAN` になるまで相手に行ごと見せない（§3.4）
>   3. ファイル名を保存しない
>   4. 送る・開くを監査ログに残す（中身は残さない）
>
> 🔴 スキルシートは引き続き提案（経路 2）で送る。チャット添付をスキルシートの抜け道にしない。

§7 の「PII 未マスキングでの外部共有 0 件」には次を足す:

> 外部共有はゲートの対象物（§3.3）。チャット添付は 2026-10-27 から対象外で、注意書き・ウイルス検査・監査ログで扱う。

## 3. 変えないもの

| ルール | 変わらない理由 |
|---|---|
| 越境の 5 経路（§3.1） | 添付は経路 3（チャット）の中の話。`ThreadParticipant` / `ThreadMember` に列挙された人だけが読む。経路は増えない |
| 取引先どうしの非可視（§3.1 の 🔴） | 1 つの部屋に入る取引先は最大 1 社のまま。別の取引先は添付の存在も知り得ない |
| ウイルス検査（§3.4） | `CLEAN` になるまで共有 URL を出さない。相手に行ごと見せない |
| 運営者に中身を見せない（§10.5） | 添付のキーは運営者に GRANT しない（既存） |
| LLM に送らない（§3.2） | 添付を AI に渡す経路を作らない |

## 4. 受け入れるリスク（宮田さんに判断してほしいこと）

- 🔴 **氏名・連絡先・単価・エンド企業名が載ったファイルを、営業が取引先へそのまま送れるようになる。** 止めるのは注意書きだけで、機械の検査は無い。
- これは今のメール添付と同じ水準。代わりに、**誰が・いつ・どの部屋に送ったか / 誰が開いたか**が監査ログに残る（メールより追える）。
- 後からゲートを足すことはできる（本文を取り出す工程ができたら、ここに戻せる）。
