## ① 人単位のチャット（DM・グループ）— いちばん急ぎ

設計案: [#125](https://github.com/Festal-KM/SES-Platform/pull/125)（`docs/chat-lane/people-chat-proposal.md`）
画面イメージ: `docs/chat-lane/people-chat-mockup.png`（#125 に同梱）

**要点**: 今のチャットは「会社と会社」の部屋だけです。これを「人と人」でも話せるようにします。
安全の仕組みはそのままにします。具体的には、**「どの会社が参加している部屋か」で他社の情報を遮る今の仕組み**（`ThreadParticipant`、`CLAUDE.md` §3.1 経路 3）は変えません。その内側に「**その会社の誰が読めるか**」を足して、さらに絞るだけです。取引先と別の取引先が同じ部屋に入ることは、今と同じくできません。

| # | 決めてほしいこと | 紺野のおすすめ |
|---|---|---|
| 1 | **`CLAUDE.md` を書き換えてよいか**。他社の情報を遮る決まり（§3.1 経路 3）に「人の段」を書き足し、用語の表（§4.1）に「部屋のメンバー」を足す | 書き換える |
| 2 | **社内だけの部屋を作れるように DB を変えてよいか**。今の部屋は「取引先 1 社」の指定が必ず要るので、自社の営業どうしの部屋が作れない | 取引先の指定を空にできるようにする |
| 3 | **取引先になった時点で、その会社とのグループを自動で作ってよいか**。取引先の招待を受け入れる流れ（宮田さんの担当部分）に、作る処理を足すことになる | 作る。足し方は相談させてください |
| 4 | **「既読」（相手が読んだか）を相手に見せてよいか**。今の `CLAUDE.md` §4.1 には「相手が読んだかは記録しない」とある。取引先が嫌がる可能性がある | 1 対 1 の DM だけで見せる、から始める（`CLAUDE.md` の書き換えが要る） |

紺野が決めたこと（参考）: 社内の DM は作れる／辞めた人の DM は残すが引き継がない／会社の管理者でも社員の DM は読めない（「誰と誰が DM を作ったか」だけ記録に残す）／チャットに貼った案件のカードは、**見る人の権限でその都度中身を出す**（取引先との部屋では、その取引先に公開済みの案件だけ。人材は貼れず「この人で提案を作る」を出す）。
