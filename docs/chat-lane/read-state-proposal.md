# 設計案: チャットの既読・未読と「未読に戻す」（S-031）

> **状態: 案（暫定）。** [#97](https://github.com/Festal-KM/SES-Platform/issues/97) の 4（未読）と 4'（既読・未読の切り替え）について、宮田・紺野の合意を取るまで実装しない（`CLAUDE.md` §8.6）。
> 合意後、この内容を `docs/02`（機能）→ `docs/04`（§3.12 / §S-031）→ `docs/05`（§3 / §4.4 / §6.5）の順に上流から反映する（`CLAUDE.md` §8.7）。
> 作成: 2026-10-14、チャットレーン（担当: 紺野）。

## 1. 何を作るか

| 機能 | 中身 |
|---|---|
| **未読の印** | スレッド一覧で、まだ読んでいない発言があるスレッドに印を付ける（名前を太字 + 点） |
| **未読の絞り込み** | 一覧を「未読だけ」に絞る |
| **会話の中の「ここから未読」** | 前回どこまで読んだかを、会話の中に 1 本の線で示す |
| **未読に戻す** | 発言を選んで「ここから未読にする」（Slack / Lark の「未読にする」と同じ）。一覧の行からも「未読に戻す」 |

やらないこと: **相手が読んだかどうか（既読 n・既読の印）は出さない**（#97 の 7。相手社の行動が見えるため、別に判断する）。

## 2. 🔴 先に決めてほしいこと

### 2.1 `CLAUDE.md` §4.1 に概念を 1 つ足す（人間の承認事項）

今の文書が未読を出していない理由は「**未読の実体が無い**」ことである（`docs/04` U-27・§S-031・ホームの `返信待ち` ③、`docs/design-system.md` §4.5 / §6 ⑬）。どれも「`messages` に既読の列が無く、近似を入れない」と書いており、**未読そのものを禁じてはいない**。むしろデザインシステム v1.0 は一覧に「未読タブ」「未読カウント（20h の円）」を描いており、ホーム（`S-003` / `S-004`）の `返信待ち` と KPI も未読チャットを母集団に予定している。

実体を作るには `CLAUDE.md` §4.1 の中核概念に **`ChatReadState`（利用者ごとのスレッドの既読位置）** を足す必要があり、これは `CLAUDE.md` の改訂 = 人間の承認事項（§8.6）である。

### 2.2 件数を出すか

| 案 | 見え方 | 根拠 |
|---|---|---|
| **A（推奨）** | デザインシステム v1.0 どおり、一覧に**未読の件数**（円）と「未読」タブ | v1.0 §3.12 の定義。件数は同じスレッドの中の自分宛の数で、他社の示唆にならない（参加は常に 2 社。`F-038` AC-1 が禁じるのは**参加していない会社**に存在・件数を知られること） |
| B | 件数は出さず、**印だけ**（太字 + 点） | 控えめに始めたい場合 |

推奨は **A**。実体ができれば、ホームの `返信待ち` ③（未読チャット）とサイドバーの `チャット` の件数バッジも描けるようになる（今は「架空の数を出さない」で止めている箇所。§6 の後続）。

## 3. データの持ち方

表を 1 つ足す: `chat_read_states`（**1 人 × 1 スレッドで 1 行**）。

| 列 | 型 | 意味 |
|---|---|---|
| `id` | `uuid` | |
| `tenant_id` | `uuid` | |
| `user_id` | `uuid` | 読んだ本人 |
| `thread_id` | `uuid` | |
| `last_read_sent_at` | `timestamptz NULL` | ここまで読んだ発言の送信時刻。`NULL` = 1 件も読んでいない |
| `last_read_message_id` | `uuid NULL` | 同じ時刻の発言を区別するための ID（並びは `(sent_at, id)`。今の会話の並びと同じ） |
| `updated_at` | `timestamptz` | |

- `UNIQUE (tenant_id, user_id, thread_id)`
- `thread_id` は `(tenant_id, thread_id)` の複合 FK で `chat_threads` を参照し、スレッドが消えたら一緒に消える（`ON DELETE CASCADE`）
- 未読かどうか = 「自分以外が送った発言で、`(sent_at, id)` が既読位置より後のものが 1 件でもあるか」
- **未読に戻す** = 既読位置を「選んだ発言の 1 つ前」に戻すだけ（新しい列は要らない）
- 行が無い = まだ開いたことがない = スレッドに自分以外の発言があれば未読

## 4. 情報境界

- 🔴 **RLS は C7 SELF**（`docs/05` §4.4。`notifications` と同じ）: `tenant_id = app_tenant_id() AND user_id = app_actor_user_id()`。**読むのも書くのも本人の行だけ**。同僚の既読位置も、相手社の既読位置も 1 行も見えない —— 「既読 n」を作れない形にしておく
- 🔴 **読めないスレッドの既読位置は作れない。** `INSERT` / `UPDATE` の `WITH CHECK` に「そのスレッドが今読める（`chat_threads` の C6 を通って行が見える）」を足す。退出したスレッドの行は残るが、スレッド一覧にも出ない
- 🔴 **未読の判定は `messages` の RLS（C6）越しに数える。** 読めない発言は数に入らないので、未読の印から他社の発言の存在は分からない
- `AuditLog` には書かない（チャットの閲覧は記録の対象外。`CLAUDE.md` §3.5 / `BR-27` と同じ）
- 運営者（管理平面）には見せない（`messages.body` と同じ扱い。件数・状態の集計にも使わない）

## 5. API（`docs/05` §6.5 の変更案）

| # | 変更 | 中身 |
|---|---|---|
| 49 | `GET /api/threads` | 各行に `unreadCount: number` を足す（案 B なら `unread: boolean` だけ）。`?unread=1` で未読だけに絞る |
| 50 | `GET /api/threads/{id}/messages` | 応答に `lastReadMessageId: string \| null` を足す（「ここから未読」の線を引く位置） |
| 新 | `PUT /api/threads/{id}/read` | 本文 `{ upToMessageId }`。既読位置をそこまで進める。🔴 **戻す方向には動かさない**（古い画面からの送信で既読が巻き戻らないように） |
| 新 | `PUT /api/threads/{id}/unread` | 本文 `{ fromMessageId? }`。その発言から未読にする（省略時 = 最後の発言だけ未読にする）。こちらは戻す方向にだけ動く |

- どちらも同じスレッドの発言 ID しか受けない（別スレッド・見えない発言は 404）
- 閲覧専用（`VIEWER` / `PARTNER_VIEWER`）も**自分の既読位置は書いてよい**（業務データではなく自分の表示の状態のため）。🔴 ただし判断が要るので合意の対象にする

## 6. 画面（`S-031`）

- **一覧**: 未読のスレッドは名前を太字にし、行の右端に未読の件数（案 A。案 B なら点）。一覧の上に「すべて / 未読」の切り替え
- **後続（同じ実体で描けるようになるもの）**: ホームの `返信待ち` ③ 未読チャット（`docs/04` §S-003 / §S-004）、サイドバーの `チャット` の件数バッジ（`docs/04` U-27）。🔴 チャットレーンの外（ホーム・サイドバー）なので、宮田さんと分担を決めてから
- **会話**: 開いたときに「ここから未読」の線を引き、その位置までスクロールする。会話の一番下が見えたら既読にする（開いただけでは既読にしない）
- **未読に戻す**: 発言にカーソルを合わせると「ここから未読にする」が出る。一覧の行にも「未読に戻す」
- **並べて開く（PR #103）**: 列ごとに同じ動き。見えている列だけ既読にする
- **スマホ**（Tier 1）: 一覧の印と「未読」の切り替えはそのまま。「ここから未読にする」は発言の長押しで出す

## 7. テスト

| 種類 | 確かめること |
|---|---|
| 分離テスト | 🔴 同僚・相手社の既読位置を 1 行も読めない / 読めないスレッドの既読位置を作れない / 他社の発言が未読の判定に入らない / 既読が巻き戻らない |
| 単体・render | 未読の判定（同じ時刻の発言、自分の発言だけのスレッド）、「ここから未読」の線、未読に戻す |
| E2E | ホストが送る → 取引先の一覧に未読の印 → 開いて最後まで見ると消える → 未読に戻すと付く |
