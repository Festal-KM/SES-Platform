# 設計案: チャットの返信スレッドと引用（S-031）

> **状態: 案（暫定）。** Issue「チャットで足したい機能」で宮田・紺野の合意を取るまで実装しない（`CLAUDE.md` §8.6）。
> 合意後、この内容を `docs/02`（機能）→ `docs/04`（§3.12 / §S-031）→ `docs/05`（§3.7 / §6.5 #50・#51）の順に上流から反映する（`CLAUDE.md` §8.7）。
> 作成: 2026-10-13、チャットレーン（担当: 紺野）。

## 1. 何を作るか

| 機能 | 中身 | 使う場所 |
|---|---|---|
| **返信スレッド** | 1 つの発言（話題）の下に返信をぶら下げる。Lark の「話題グループ」に当たる | 案件スレッド（話題型の並べ方） |
| **引用** | 特定の発言を引いて返す。返信の先頭に元の発言の抜粋を出す | 案件スレッド・企業スレッドの両方 |

目的は、案件ごとのやりとりを「話題ごと」に追えるようにし、別の話題が割り込んでも流れを見失わないようにすること。

## 2. データの持ち方

`messages` に 2 列を足す（どちらも任意）。

| 列 | 型 | 意味 |
|---|---|---|
| `reply_to_message_id` | `uuid NULL` | 返信先の話題（根の発言）。`NULL` = 話題そのもの（根） |
| `quote_message_id` | `uuid NULL` | 引用元の発言。`NULL` = 引用なし |

守ること（DB で担保する）:

1. 🔴 **返信先・引用元は同じスレッドの発言に限る。** `messages` に `UNIQUE (tenant_id, thread_id, id)` を足し、2 列とも `(tenant_id, thread_id, <列>)` の複合 FK で参照する。別スレッド・別テナントの発言を指す行は DB が拒否する（アプリの検査に頼らない）
2. 🔴 **返信の深さは 1 段まで。** 返信に返信はぶら下げない（Lark と同じ）。`reply_to_message_id` が指す行の `reply_to_message_id` が `NULL` であることをトリガで検査する
3. 返信先・引用元が後から本文削除（`PURGED` / 保持期間）されても行は残る。画面は「削除された発言」と出す（今の `messages.purged` と同じ扱い）

## 3. 情報境界（`CLAUDE.md` §3.1 経路 3）

- 🔴 **新しい越境経路を作らない。** 返信も引用も同じスレッドの `messages` の行であり、既存の RLS（C6 THREAD: 参加会社だけが読める）がそのまま効く。`owner_partner_company_id` の継承も今の行と同じ
- 🔴 **引用の抜粋は、読み手が元の発言を読めるときだけ出す。** 抜粋は API が RLS を通して読み直して返し、読めなければ「表示できない発言」とする（同じスレッドなので通常は読めるが、退出した会社の扱いなどで差が出たときに漏らさない）
- 返信の件数（`replyCount`）は同じスレッドの中の件数であり、他社の示唆にならない（スレッドの参加は常に 2 社）

## 4. API（`docs/05` §6.5 の変更案）

| # | 変更 | 中身 |
|---|---|---|
| 50 | `GET /api/threads/{id}/messages` | 話題型のスレッドでは**根の発言だけ**を返し、各行に `replyCount` / `lastReplyAt` を付ける。`?replyTo={messageId}` を付けると、その話題への返信を古い順に返す |
| 51 | `POST /api/threads/{id}/messages` | 本文に `replyToMessageId?` / `quoteMessageId?` を足す。同じスレッドでない・深さ 2 段になる指定は 422 |
| 応答の型 | `ChatMessageView` | `replyToMessageId` / `replyCount` / `lastReplyAt` / `quote: { id, senderName, excerpt } \| null` を足す。🔴 抜粋は先頭 80 文字まで |

## 5. 画面（`S-031`）

- **案件スレッド（話題型）**: 根の発言の下に「返信 3 件・最終 18:57」を出す。押すと右の関連情報パネルの位置に返信の一覧と入力欄が開く（Lark / Slack と同じ）
- **企業スレッド（会話型）**: 返信スレッドは使わない。引用だけを使う
- **引用**: 発言にカーソルを合わせると「引用して返信」が出る。入力欄の上に引用元の抜粋が付き、送信すると吹き出しの上に抜粋が出る
- 品質ゲートの扱いは、本文だけの投稿と同じ（#89 の結論に従う）

## 6. テスト

| 種類 | 確かめること |
|---|---|
| 分離テスト | 🔴 他社（別パートナー）が返信と引用の抜粋を 1 件も読めない / 別スレッドの発言を返信先・引用元にできない（DB が拒否）/ 深さ 2 段を拒否 |
| 単体・render | 返信件数の表示、引用の抜粋、削除された引用元の表示 |
| E2E | ホストと取引先が同じ話題に返信し合える。取引先 B からは見えない |

## 7. 進め方

1. この案を Issue に付けて合意を取る
2. マイグレーション（2 列 + 複合 FK + トリガ）は、宮田さんにタイミングを伝えてから 1 本で入れる（共有物のため）
3. 分離テストを先に書き、RLS とFK が効いていることを確かめてから API と画面を作る

## 8. 決めること（Open Questions）

- 企業スレッド（会話型）でも返信スレッドを使えるようにするか（案では使わない）
- 返信の通知を誰に送るか（話題の発言者だけ / スレッドの全員）。@メンションの通知と合わせて決める
- 引用の抜粋の長さ（案では 80 文字）
