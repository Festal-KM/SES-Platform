## 1. 何を作るか

```
チャット（A社）                               ← 会社とのふだんの会話（親）
 ├ スレッド：案件「金融系Web基盤」について        ← 案件ベース（今もある）
 ├ スレッド：提案「山田さん → 金融系Web基盤」について ← 人ベース（新）
 ├ スレッド：稼働「山田さん（〜12/31）」について    ← 人ベース（新）。延長・単価の相談
 └ チャットの発言から「スレッドにする」で切り出す   ← 新
```

| 機能 | 中身 |
|---|---|
| **スレッドを起こす** | 案件・提案・稼働の画面と、チャットの発言から、その相手との「〜について」のスレッドを起こす。🔴 **今は案件スレッドを誰も新しく作れない**（seed 以外から生まれない。`docs/04` `Q-04-10`）ので、その解決を兼ねる |
| **人についてのスレッド** | エンジニア個人の話を、**提案**または**稼働**に結びつけたスレッドで行う |
| **切り出し** | チャットの発言に「スレッドにする」を出す。対象（案件・提案・稼働）を選ぶと、その発言を先頭に引いたスレッドができ、元の発言には「スレッドに移動しました」の印が付く |

## 2. 🔴 人についてのスレッドは「エンジニア」ではなく「提案」「稼働」に結びつける

エンジニアそのものに結びつけると、**相手の会社に見せてよいエンジニア情報の範囲が決まらない**。

| 結びつける先 | ホストが見えるもの | 取引先が見えるもの | 越境経路 |
|---|---|---|---|
| ~~エンジニア~~ | 取引先のエンジニアは**台帳を読めない**（経路 2 / 4 以外） | ホストのエンジニアは**読めない** | 🔴 新しい経路になる（作らない） |
| **提案**（`Proposal`） | 提案時点の凍結情報（`EngineerSnapshot`） | 自社の提案 | **経路 2 の範囲内** |
| **稼働**（`Assignment`） | 自社の稼働 | 自社所属エンジニアの稼働（4 項目） | **経路 5 の範囲内**。🔴 仕様が既に「延長の意思表示・単価の交渉はチャット（経路 3）で行う」と決めている（`CLAUDE.md` §3.1-5 / `BR-68` / `UC` の手順 3）。その置き場所になる |

- **スレッドの画面に出すのは、両者が既に見えている項目だけ**: 提案 = 案件名・状態・提案日 / 稼働 = 案件名・稼働期間・満了日・延長確認の状態。🔴 単価・エンド企業名・`ExtensionReview` の中身（ホスト内部の検討）は出さない
- **匿名候補（経路 4）にはスレッドを作らない**。匿名のまま会話を始めると、会話の中で実名や所属が漏れる。提案依頼（`ProposalRequest`）を応諾して提案ができてから、提案のスレッドを起こす

## 3. データの持ち方

`chat_threads` を広げる（新しい表は作らない）。

| 変更 | 中身 |
|---|---|
| `kind` | `'PROJECT' \| 'COMPANY'` に **`'PROPOSAL'` / `'ASSIGNMENT'`** を足す（CHECK の変更） |
| `proposal_id` | `uuid NULL`。`(tenant_id, proposal_id)` の複合 FK |
| `assignment_id` | `uuid NULL`。`(tenant_id, assignment_id)` の複合 FK |
| `origin_message_id` | `uuid NULL`。切り出し元の発言（`(tenant_id, thread_id, id)` の複合 FK で**同じ相手との親チャットの発言**に限る） |
| CHECK | `kind` ごとに対象が 1 つだけ埋まる（`PROJECT` → `project_id`、`PROPOSAL` → `proposal_id`、`ASSIGNMENT` → `assignment_id`、`COMPANY` → どれも `NULL`） |
| 一意 | 今の `UNIQUE (tenant_id, kind, project_id, partner_company_id)` を対象ごとに張り直す（**同じ相手・同じ対象のスレッドは 1 本**） |

- 🔴 **スレッドの相手（`partner_company_id`）は対象から決まる**（提案 = 提案した会社、稼働 = 当事者の会社）。入力で受けない —— 「別の会社との提案スレッド」を作れない
- 参加会社（`thread_participants`）は今と同じく**ホスト + その 1 社**に固定（`F-038 AC-2`）

## 4. 誰が起こせるか（`Q-04-10` の結論案）

| 対象 | ホスト | 取引先 | 条件 |
|---|---|---|---|
| 案件 | ✅ | ✅ | 🔴 **その取引先に公開済み（`ProjectVisibility`）の案件だけ**。ホストが未公開の案件でスレッドを起こすと、案件の存在を取引先に知らせることになる |
| 提案 | ✅ | ✅（自社の提案） | 提案が `SUBMITTED` 以降（`DRAFT` / ゲート中は社内の段階） |
| 稼働 | ✅ | ✅（自社エンジニアの稼働） | 経路 5 で読める稼働だけ |

- `docs/04` `Q-04-10` の既定値は「ホストだけが起こせる」（取引先が起点になると、どのホストと話せるかを探索できるため）。🔴 本案は**対象が既に両者に見えているときだけ**起こせるので、探索にならない。**取引先も起こせる形を推奨**するが、宮田さんの判断に委ねる
- `VIEWER` / `PARTNER_VIEWER` は起こせない（投稿できないロールと同じ）

## 6. 画面（`S-031` ほか）

- **一覧の木**（#106）: 会社のチャットの下に、案件・提案・稼働のスレッドを種類ごとに並べる（「案件」「提案」「稼働」の小見出し）
- **チャットの発言**: カーソルを合わせると「スレッドにする」→ 対象を選ぶ（その相手との公開済み案件・提案・稼働だけが候補）
- **入口**: `S-011` 案件詳細「この案件でやり取りを始める」/ `S-023` 提案詳細 / `S-029` 稼働（満了アラートからも）。🔴 これらはチャットレーンの外の画面なので、宮田さんと分担を決めてから
- モバイル（Tier 1）: 「スレッドにする」は発言の長押し

## 7. テスト

| 種類 | 確かめること |
|---|---|
| 分離テスト | 🔴 未公開案件・他社の提案・他社の稼働でスレッドを起こせない（404）/ 相手の会社を入力で差し替えられない / 他の取引先は切り出したスレッドの存在を知れない / 切り出し元は同じ相手の親チャットの発言に限る |
| 単体・render | 対象ごとの要約が §2 の項目だけ / 重複作成で既存を返す |
| E2E | ホストが案件から起こす → 取引先が返信 / 取引先が稼働のスレッドで延長の相談 → ホストに届く |
