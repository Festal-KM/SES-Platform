🔴 **[Issue #3](https://github.com/Festal-KM/SES-Platform/issues/3) の回答を督促する**（E-11）。論点は「**稼働開始日の大幅な遅れと勤務地の不一致を『減点』で扱うか『候補から外す』か**」。

## 5. テスト計画（方針）

- **ユニット**: スコア関数の決定性（同一入力 100 回で同一出力）。足切り・6 因子の境界値。重みを変えたときの順位変化。`domain-purity.test.ts` の維持。
- **結合**: `MatchCandidate` の生成と `rationale` の付与。根拠文の 1 リクエスト集約。
- **E2E**: 🔴 **匿名候補が自社エンジニアと同じ基準でスコアリングされ、匿名のままスコア順に並ぶ**（`CLAUDE.md` §5 の成功条件）。根拠文に 5 項目を超える情報が現れない。
- **外部 API のモック**: 🔴 **`MockAnthropicClient` を E2E と結合で同一実装として使う**（`docs/05` §17.5）。根拠文の固定応答 + スキーマ違反・タイムアウトの再現。

## 6. 完了判定（方針）

1. `F-029` / `F-030` / `F-031` の全 AC が green。
2. 🔴 **匿名候補が匿名のままスコア順に並ぶことを E2E で証明できる**（`CLAUDE.md` §5 Phase 2 の成功条件）。
3. 🔴 **スコアが決定的**（同一入力で同一出力）。順位を LLM が決めていない。
4. 🔴 **根拠文の自動生成が上位 10 候補に限られ、1 リクエストに集約されている**（原価の最大の調整弁）。
5. マッチング候補の初回提示が p95 3 秒以内。
6. 🔴 **`staging` が立ち上がり、外部 API が各サービスの sandbox エンドポイントに向いている**（T-13-09。`PM-Q-3` / [Issue #20](https://github.com/Festal-KM/SES-Platform/issues/20)）。**`production` の API キーが設定されていたら起動に失敗する**ことを `staging` でも確認している。
