## 1. 目的

**越境経路 3（チャット）** を開き、通知とタスクの基盤を作る。あわせて **重複提案の検知**（ホストのみ表示）と **面談日程調整の連絡**（冪等な外部送信）を入れる。

🔴 **本スプリントで開く経路 3 は、`ThreadParticipant` に列挙された会社だけが読める**（`CLAUDE.md` §3.1）。**参加会社の判定を接続中も毎イベントで再評価する。**

## 5. テスト計画（方針）

- **ユニット**: 通知の宛先解決。タスクの期日計算（`now` を引数で渡す）。重複提案の照合（決定的）。
- **結合**: C6 の実データ検証（`ThreadParticipant` に無い会社は 0 件）。SSE の再判定（参加解除後にイベントが届かない）。`send.interview-invite` の冪等性。整合層への重複提案の追加で合否が決定的なまま。
- **E2E**: 🔴 **パートナー A の画面・API・通知に、B が同一案件に提案していることの示唆（重複提案の指摘を含む）が 0 件**（`F-004 AC-4` / `F-037 AC-1` / `BR-07` / `BR-08`）。チャット添付が `CLEAN` かつゲート PASS でなければ送れない。**Tier 1 の画面（`S-024` / `S-031` / `S-032` / `S-033`）はモバイルで操作まで完結する。**
- **外部 API のモック**: 面談調整メールは**分類 3（提案先）であり全非本番環境でモック**。通知メールは宛先分類で分岐（SP-04 の単一経路）。
