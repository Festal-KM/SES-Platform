## 1. 目的

🔴 **`CLAUDE.md` §10.2 が「管理平面の筆頭機能」と定める原価・粗利の可視化**を成立させる。受け入れ基準は **「使えば使うほど赤字になるテナントを、月次を待たずに検知できること」**。

## 5. `F-063` で守ること（`CLAUDE.md` §10.2）

- **テナント × 月で、売上（サブスクリプション + 従量）と原価（AI / メール / ストレージ）と粗利を並べて表示する。** 🔴 **電子署名は BYO のため原価に含めない**（`costEsignUsd` は常に 0。`docs/03` `pm` 申し送り 9-①③）。
- **原価は §12 の AI 運用ロール別に分解できること。** 「どのロールが原価を食っているか」が分からないと改善対象を特定できない。
- **粗利率の閾値はプランごとに設定できる**（`F-063 AC-3`）。
- 🔴 **表示されるのは金額・件数・率のみで、業務データの内容に到達する導線が存在しない**（`F-063 AC-4` / `BR-40`）。
- 🔴 **運営者には「金額上限に対する消費率」と「基準ユニット比の倍率」の両方を表示する。金額（USD）はここ（`A-004` / `A-011`）にのみ現れ、テナント側の画面には現れない**（`F-063 AC-5` / `F-027 AC-6`）。
- **件数（利用者に見せている単位）と金額の対応が同一画面で確認でき、1 件あたり標準原価の改定時に両者の乖離を検知できる。**

## 6. テスト計画（方針）

- **ユニット**: 粗利の算出（`docs/02` 章 7.5 の定義）。超過件数の算出（`max(0, AI_UNIT_* − クォータ)`）。基準比の倍率。
- **結合**: `BillingMeterSubmission` の `UNIQUE` による二重送信の防止（同月 2 回実行で Stripe 呼び出しが 1 回）。`SUSPENDED` の実行系拒否（全ロール × 全実行系ルート）。`PLATFORM_SUPPORT` のライフサイクル遷移が 403。
- **静的テスト**: `tenant-usage-no-money.test.ts`（主平面に金額が出ない。SP-10 で作成済みの維持）/ `execute-guard.test.ts`（`SUSPENDED` を含む全実行系ルート）。
- **E2E**: `F-062 AC-4`（`SUSPENDED` でログイン・閲覧はでき実行系が拒否され、データが削除されない）。`F-063 AC-1`（粗利率が閾値を割ったテナントが日次の更新で上位に現れる）。E2E #16（削除完了の確認が `A-010` の 1 本のみ。SP-10 の維持）。
- **外部 API のモック**: 🔴 **Stripe は `packages/connectors/src/mock/stripe/**`**（`docs/05` §17.5）。Webhook は `constructEvent` を必須にし、フィクスチャで検証する。
