# ワイヤーフレーム — SES Platform（仮称）

`docs/04-ui-design.md`（APPROVED 済み）の全 57 画面に対応するワイヤーフレーム生成プロンプトを置く。
画像は `scripts/generate-wireframes.mjs` が `prompt.md` を機械的にパースして生成する。

- **主平面** `S-001`〜`S-043`（43 画面）
- **管理平面** `A-001`〜`A-014`（14 画面）

## 生成

```bash
node scripts/generate-wireframes.mjs --dry-run          # 対象と枚数の確認（API を呼ばない）
node scripts/generate-wireframes.mjs                    # 未生成の画像をすべて生成
node scripts/generate-wireframes.mjs --screen S-021     # 特定画面のみ
node scripts/generate-wireframes.mjs --force            # 既存画像も再生成（課金が発生する）
```

API キーは**プロジェクト直下の `.env` / `.env.local`** から読む（`.env.example` 参照）。
**画像生成は 1 枚ごとに課金される。** `--force` での全画面再生成は理由を確認してから実行すること。

## 枚数方針（`docs/04` 後続エージェントへの申し送り 10）

| 対象 | 枚数 | バリアント |
|---|---|---|
| 主平面 **Tier 1** の 12 画面 | 各 3 枚 | `desktop.png` / `tablet.png` / `mobile.png` |
| 主平面 **Tier 2 / Tier 3** の 31 画面 | 各 1 枚 | `desktop.png` |
| 管理平面 14 画面（全画面 T3） | 各 1 枚 | `desktop.png` |
| **合計** | **81 枚** | |

Tier 1 の 12 画面: `S-001` `S-002` `S-003` `S-004` `S-017` `S-018` `S-021` `S-024` `S-030` `S-031` `S-032` `S-033`（`docs/04` §1.1）。

🔴 **この内訳を超えて枚数を増やさない。** Tier 2 / Tier 3 の劣化のさせ方は `docs/04` の各画面「デバイス別」に文章で定義済みであり、
空状態・ローディング・エラーは各 `prompt.md` の 1 枚の中に「状態ストリップ」として描き込んでいる（バリアント画像を増やしていない）。

## `prompt.md` の構造（スクリプトのパース契約）

- `## 共通プロンプト` は **1 ファイルに 1 つだけ**。その最初のコードブロックが全画像に前置される
- 各画像は `## {ファイル名}.png プロンプト` の最初のコードブロック
- API に送られるのは `共通プロンプト + "\n\n---\n\n" + 各バリアントのプロンプト`
- `mobile` のみ縦長、それ以外（`desktop` / `tablet`）は横長が自動で選ばれる
- 生成しない画像のセクションは書かない（空セクションはパースエラーになる）

詳細は `.claude/agents/designer.md` を参照。

## 描画上の固有ルール（`docs/04` 申し送り 1〜11）

1. **`S-021`（提案の承認）はデスクトップ / タブレット / モバイルの 3 枚必須**。モバイルは 1 本の縦スクロールで、タブでもアコーディオンでもない
2. **一覧はテーブル**。カードで並べない（主平面 8〜12 行、管理平面 10〜15 行）
3. **`S-003` / `S-004` を「KPI カード 4 枚 → グラフ → アクティビティ」で描かない**。最上部は 1 本のテーブル
4. **ナビ・見出し・ボタン・状態バッジにアイコンを付けない**。AI 機能に比喩アイコン（きらめき等）を使わない
5. **`S-016` は自社候補と匿名候補を同じテーブルに混在**させる。匿名候補は丸めた値（`5〜10 年` / `60〜70 万円` / `翌月` / `東京都・一部リモート可` / スキル上位 8 件）
6. **`A-002` / `A-005` は異常が上位に来ている並び**で描く
7. **`sandbox` の環境バナーは 3 点構成を折り返して全文**描く。「メールは一切送信されません」とも「すべてのメールが届きます」とも書かない
8. **管理平面は主平面と視覚的に区別**する（全幅の黒帯 `運営者コンソール` / 横並びタブ / `閲覧のみ（テナント業務データに対して）` の常時表示）
9. **`S-039` に `gate-inspector` の行を描かない**（グレーアウトも注記も置かない）。`A-011` のロール別原価内訳は 6 ロールで正しい
10. **パートナー同士の相互参照を示唆しない**（他社の件数・存在・順位・「他にも提案があります」を描かない）
11. **`A-014` は確認ステップの直前に「開設後に自動で入る既定値」ブロック**を必ず描く

## 環境バナーを描いている画面

`production` 以外でのみ表示される帯であり、全画面に描くと誤解を生むため、**環境が画面の内容に関わる 5 画面のみ**で描いている。
それ以外の画面は `production` を描いており、バナーは存在しない。

| 画面 | 環境 | 理由 |
|---|---|---|
| `S-001` サインイン | `sandbox` | `docs/04` §4.1 がセクション 5 として環境バナーを列挙している |
| `S-014` 取引先企業の招待 | `sandbox` | 招待リンクの手渡し導線が `sandbox` 固有（`F-007 AC-4`） |
| `S-036` 送信ドメイン | `sandbox` | 共通ドメインで動作し検証が不要という `sandbox` 固有の状態がある |
| `S-043` サンドボックスの状況 | `sandbox` | 画面自体が `sandbox` にのみ存在する |
| `A-012` デモ環境データ | `demo` | 画面自体が `demo` にのみ存在する（`F-053 AC-6`） |
| `A-014` テナントの開設 | `sandbox` | セクション 1 が `APP_ENV` を読み取り専用で示すため |
