# ワイヤーフレーム — SES Platform（仮称）

`docs/04-ui-design.md`（改訂 5・APPROVED 済み）の全 60 画面に対応するワイヤーフレーム生成プロンプトを置く。
画像は `scripts/generate-wireframes.mjs` が `prompt.md` を機械的にパースして生成する。

- **主平面** `S-001`〜`S-046`（46 画面。`S-046` は改訂 5 = Issue #30 既定値②で新設されたパスワード再設定画面）
- **管理平面** `A-001`〜`A-014`（14 画面）

## 生成

```bash
node scripts/generate-wireframes.mjs --dry-run          # 対象と枚数の確認（API を呼ばない）
node scripts/generate-wireframes.mjs                    # 未生成の画像をすべて生成
node scripts/generate-wireframes.mjs --screen S-021     # 特定画面のみ
node scripts/generate-wireframes.mjs --force            # 既存画像も再生成（課金が発生する）
```

API キーは**プロジェクト直下の `.env` / `.env.local`** から読む（`.env.example` 参照）。
**画像生成は 1 枚ごとに課金される。** `--force` での全画面再生成は理由を確認してから実行すること。

## `prompt.md` の構造（スクリプトのパース契約）

- `## 共通プロンプト` は **1 ファイルに 1 つだけ**。その最初のコードブロックが全画像に前置される
- 各画像は `## {ファイル名}.png プロンプト` の最初のコードブロック
- API に送られるのは `共通プロンプト + "\n\n---\n\n" + 各バリアントのプロンプト`
- `mobile` のみ縦長、それ以外（`desktop` / `tablet`）は横長が自動で選ばれる
- 生成しない画像のセクションは書かない（空セクションはパースエラーになる）

詳細は `.claude/agents/designer.md` を参照。

## 描画上の固有ルール（`docs/04` 申し送り 1〜13）

1. **`S-021`（提案の承認）はデスクトップ / タブレット / モバイルの 3 枚必須**。モバイルは 1 本の縦スクロールで、タブでもアコーディオンでもない
2. **一覧はテーブル**。カードで並べない（主平面 8〜12 行、管理平面 10〜15 行）
3. **`S-003` / `S-004` を「KPI カード 4 枚 → グラフ → アクティビティ」で描かない**。最上部は 1 本のテーブル
4. **ナビ・見出し・ボタン・状態バッジにアイコンを付けない**。AI 機能に比喩アイコン（きらめき等）を使わない
5. **`S-016` は自社候補と匿名候補を同じテーブルに混在**させる。匿名候補は丸めた値（`5〜10 年` / `60〜70 万円` / `翌月` / `東京都・一部リモート可` / スキル上位 8 件）
6. **`A-002` / `A-005` は異常が上位に来ている並び**で描く
7. **`sandbox` の環境バナーは 3 点構成を折り返して全文**描く。「メールは一切送信されません」とも「すべてのメールが届きます」とも書かない
8. **管理平面は主平面と視覚的に区別**する（全幅の黒帯 `運営者コンソール` / **横並びタブ 5 グループ**（監視 / テナント / 契約 / 記録 / 運用）/ `閲覧のみ（テナント業務データに対して）` の常時表示）
9. **`S-039` に `gate-inspector` の行を描かない**（グレーアウトも注記も置かない）。`A-011` のロール別原価内訳は 6 ロールで正しい
10. **パートナー同士の相互参照を示唆しない**（他社の件数・存在・順位・「他にも提案があります」を描かない）
11. **`A-014` は確認ステップの直前に「開設後に自動で入る既定値」ブロック**を必ず描く。**送信ドメインの登録欄（セクション 5b）も描く**
12. 🔴 **`S-044` / `S-045`（越境経路 5・取引先ビュー）は「読み取り専用であること」が絵から分かるように描く** — 一覧 + 右パネルで、書き込みボタンは「相談する（チャットへ）」のみ（`S-045` の最終版ダウンロードは読み取り操作であり例外ではない）。ホストの販売単価・エンド企業名・粗利の欄はグレーアウトでも空欄でもなく描かない。`S-045` の一覧は `最終更新` 列を持たない 4 列ちょうど。`S-044` のモバイル行はエンジニア名を先頭に置いたうえで既存 4 項目を 1 つも省略しない。`S-025` / `S-029` からは「取引先にはこう見えています」の secondary ボタンで開き、`S-044` / `S-045` 側にプレビュー時の全幅帯を描く
13. 🔴 **`S-020` / `S-021` / `S-026` の AI 日次コスト上限による停止は「`検査中` のまま + 停止理由 + 再開条件」で描く。`GATE_FAILED` の橙にしない。**「修正して再実行」のボタンも描かない。**停止対象は PII 層・商流層の 2 層のみ**（AI 依存のため）。**整合層は機械照合のみで完結するため PASS のまま保持し `検査中` にしない**
14. 🔴 **`S-037` は資格情報の入力フォームを持たない**。「DocuSign に接続する」ボタン → 同意画面 → 戻る、の 3 ステップとして描き、クラウドサイン・GMO サインなどの選択肢は描かない
15. 🔴 **`S-038` / `A-004` / `A-011` は金額表記の扱いが違う**。`S-038`（利用者向け）は件数 4 種のメーター + メール + ストレージ + 席数 + 超過分の請求見込み（金額はここのみ）で、AI の 1 日のコスト上限はゲージにしない。`A-004` / `A-011`（運営者向け）は金額と件数の両方 + 基準ユニット比の倍率を併記する。**AI コスト消化率は遮断器であり 100% を超える表示を作らない**（`A-004`）
16. 🔴 **業務画面に AI 運用ロールの内部識別子を描かない**（`S-038` 含む）。内部識別子を出してよいのは `S-039` のモデル設定行と `A-011` のロール別原価内訳のみ
17. **否定指示（〜を描かない）で禁止対象を書くときは、AI 利用量・クォータ・内部識別子など「誤って描かれると統制違反になる語」に限り、旧版の文言や内部識別子を丸ごと引用しない。** 描画モデルが否定文中の文字列をそのまま描いてしまう事故を避けるため、一般的な説明に言い換える。**射程はここまで** — バッジ名・金額例・固有名詞など統制違反にならない語を否定文で挙げること自体は許容する（`S-013` `S-026` `S-029` `S-037` `S-043` `S-044` `S-045` など、Iteration 1 で承認済みの記述は書き換えを求めない）
18. 🔴 **共有フィクスチャ（`〇〇システム` / `山田（営業）` / `通知 5`）は同一時点 = AI 停止中で描く。画面ごとに時点を変えない**（Iteration 5・オーケストレーター決定）。`S-038` の `AI 停止中` filled badge・停止対象の列挙、`A-004` の `AI コスト 100%`、`S-035` の件数クォータ要約、`S-032` のヘッダと通知本文、`S-003` のヘッダは、すべて同一テナント・同一時点の状態を描く

## 環境バナーを描いている画面

`production` 以外でのみ表示される帯であり、全画面に描くと誤解を生むため、**環境が画面の内容に関わる 6 画面のみ**で描いている。
