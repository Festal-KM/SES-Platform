# 90. トラブルシューティング

ハーネスが期待どおり動かないときの切り分け。

---

## 🔴 まず疑うのは `CLAUDE.md` §3

**このハーネスの不調の大半は `CLAUDE.md` §3（ハードルール）の弱さに起因する。**

`design-reviewer` と `code-reviewer` は §3 を照合基準として動く。§3 が「適切に検証する」「気をつける」レベルだと、**レビューは何も判定できず「特に問題ありません」を返し続ける**。

症状として現れるのは以下：

- レビューが常に `APPROVED` を即返す
- 指摘が抽象的（「もっと良くできる」「考慮が必要」）
- 明らかなハードルール違反が素通りする

対処: `CLAUDE.md` §0 の「良いハードルールの条件」に照らして §3 を書き直す。

---

## ループが収束しない

### `/design-iterate` が 5 周して `ESCALATE`

| 原因 | 見分け方 | 対処 |
|---|---|---|
| 上流ドキュメント間に矛盾がある | 毎回違う箇所を指摘される | 上流を先に `/design-iterate` で確定させる |
| `CLAUDE.md` の記述が不足 | 同じ指摘が繰り返される | `CLAUDE.md` を人間が直す（§8.6） |
| レビュー観点が広すぎる | 指摘件数が毎回 10 件超 | 「今回は §N の観点だけレビューして」と絞る |
| 要求が矛盾している | reviewer の指摘 A と B が両立しない | 人間がどちらを取るか決める |

### `/iterate` が 5 周して `ESCALATE`

| 原因 | 見分け方 | 対処 |
|---|---|---|
| タスクが大きすぎる | `programmer` の変更ファイルが 10 個超 | `pm` で再分解する |
| `docs/05` の設計に問題がある | 同じ指摘で 3 周以上 | ループを止め `/design-iterate program-design` |
| 環境不備 | `e2e-tester` が毎回 `BLOCKED` | DB / ワーカー / モックの起動を確認 |
| ハードルールが矛盾 | reviewer が両立不能な要求をする | `CLAUDE.md` §3 を人間が直す |

🔴 **同じループを 6 周目に入れない。** 収束しないループは、回すほど文脈が汚れて悪化する。

---

## 出力が途中で切れる

**原因**: 出力トークン上限（1 回の書き込みが大きすぎる）。エージェントが死んでファイルごと失われることもある。

**対処**: 分割書き込みを指示する。

```
ドキュメントが長くなるので、以下の手順で分割して書いてください:
1. まず見出しの骨格 + §1 だけを Write で作る
2. 以降は 1 章ずつ Edit で追記する
3. 1 回の書き込みは 300 行以内に収める
4. 各章の追記後に wc -l で行数を確認する
```

これは `.claude/agents/*.md` の出力制約にも書かれているが、長大なドキュメントでは明示的に念押しすると安定する。

## 生成物が薄い / 具体性がない

| 症状 | 原因 | 対処 |
|---|---|---|
| `docs/01` が一般論の羅列 | ブリーフの「なぜ回っていないか」が弱い | `prompts/00-project-brief.md` §2 を書き直す |
| `docs/02` の受け入れ基準が判定不能 | `docs/01` の `BR-xx` が抽象的 | `docs/01` を先に直す |
| `docs/03` の数値に出典が無い | 裏取りが行われていない | 「出典 URL の無い数値は『未確定』と書いて」と指示し直す |
| `docs/05` が「気をつける」で終わる | ハードルールの担保機構が指定されていない | 「型 / DB 制約 / Lint / 実行時ガードのどれで担保するか明示して」と指示 |
| レビューが甘い | §3 と §7 が弱い | 上の「まず疑うのは §3」へ |

## エージェント固有の問題

### `tech-selection` が推測で数値を書く

```
docs/03 を見直してください。
外部 API の数値（レート上限・単価・無料枠）のうち、
公式ドキュメントで裏取りできていないものを「未確定」に書き換え、
確認すべき URL を併記してください。

🔴 推測値を確定値として書かないでください。
下流がこれを確定値として扱うため、推測は事故になります。
```

### `designer` が管理平面を後回しにする

```
docs/04 の A-xxx（管理平面）の画面についても、
S-xxx と同じ密度で prompt.md を作成してください。
管理平面を薄くすると運用できない製品になります（CLAUDE.md §10）。
```

### 画像生成が 429 で大量に失敗する

**原因**: 同時実行数が高すぎる。画像生成 API のレート上限は**公称値より実測が厳しい**ことがある。

```bash
node scripts/generate-wireframes.mjs --concurrency 2
```

**429 の失敗は課金されない。** 未生成分だけが対象になるので `--force` は不要。そのまま再実行してよい。

### `code-reviewer` が項目を `N/A` にしすぎる

`/iterate` に補足を添える：

```
/iterate T-02-05

このタスクは CLAUDE.md §3.1（データ分離）と §3.4（冪等性）に触れます。
該当項目を N/A にせず、必ず検査してください。
```

### `e2e-tester` が毎回タイムアウトする

**よくある原因**: **ジョブワーカーを起動し忘れている**。非同期ジョブが進まないため、状態遷移のポーリングが必ずタイムアウトする。

`docs/05` のテスト戦略に、必要なプロセス（dev サーバ / ジョブワーカー / モックサーバ）の起動手順を明記する。

## 🔴 即座に止めるべき状況

| 状況 | なぜ危険か | 対処 |
|---|---|---|
| エージェントが実 API を叩こうとしている | **不可逆な事故**（外部への書き込みは取り消せない） | 即ループ停止。モック設定を確認 |
| `production` 向けの設定変更をしようとしている | 本番事故 | 即停止。人間が判断（§8.6） |
| `CLAUDE.md` を書き換えようとしている | 全エージェントの一次資料。改訂は承認事項 | 即停止。差分を人間が確認 |
| DB マイグレーションを本番に当てようとしている | 不可逆 | 即停止 |

## 終端文字列が返ってこない

ループは応答末尾の文字列で継続を判定する。**文字列が無い応答は契約違反として停止する仕様**。

| エージェント | 期待される終端 |
|---|---|
| `programmer` / `e2e-tester` | `## DONE` / `## BLOCKED: <理由>` |
| `code-reviewer` / `design-reviewer` | `## APPROVED` / `## REQUEST_CHANGES` / `## ESCALATE: <理由>` |
| `pm`（完了確認） | `## PHASE_COMPLETE` / `## PHASE_INCOMPLETE: N 件` |

返ってこない場合、たいてい**出力が途中で切れている**（上の「出力が途中で切れる」参照）。分割して再実行する。

## 切り分けの順番

問題が起きたら、この順で疑う：

```
1. CLAUDE.md §3 は機械的に判定できる形か
2. CLAUDE.md §7 に「0 件」の事故が書かれているか
3. 上流ドキュメントが APPROVED を得ているか
4. タスクの粒度は 1 回の /iterate に収まるか
5. 環境（DB / ワーカー / モック）は起動しているか
6. 出力が途中で切れていないか
```

1 と 2 で解決することが最も多い。
